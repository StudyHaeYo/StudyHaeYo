# 프로젝트 소개

기준 시점: 2026-10-20 (`main` b387501 기준)

## 한 줄 정의

Notion처럼 학습 페이지를 자유롭게 만들고, 그 페이지에서 쌓인 학습 기록을 분석해 다음 학습(복습)으로 연결하는 개인 학습 관리 서비스. 단순한 Notion 복제가 아니라 "학습 데이터를 다시 다음 학습에 연결하는 것"이 핵심이다.

```
학습 계획 → 학습 페이지 → 실제 학습 → 학습 기록 → 분석 → 복습 → 다시 학습 페이지
```

## 각 개념의 역할

| 개념 | 역할 | 하지 않는 것 |
|---|---|---|
| 학습 페이지 | 무엇을 공부하는가. 본문과 속성을 가진다 | |
| 학습 기록 | 실제로 무엇을 했는가. 페이지에 딸린 데이터다 | 사이드바 트리의 노드나 별도 페이지 타입이 아니다 |
| 학습 계획 | 앞으로 무엇을 할 것인가 | |
| Home | 지금 무엇을 해야 하는가 | 전체 통계를 보여주지 않는다 |
| 학습 분석 | 지금까지의 상태가 어떤가 | |
| 복습 | 기존 페이지로 돌아가 다시 공부하는 행동 | 페이지 타입이 아니다 |
| AI | 열려 있는 페이지의 내용을 돕는 도구 | 페이지 타입이 아니다 |

## 팀과 도구

- 이재윤: 프론트엔드. v0로 UI 개발.
- 김준혁: 백엔드/DB/API/분석 로직.
- 코드: GitHub `StudyHaeYo/StudyHaeYo`. `main`이 공식 코드이고, 배포는 `main` → Vercel(studyhaeyo.vercel.app).
- 스택: Next.js(App Router), TypeScript, Tailwind, shadcn/ui, lucide-react.
- 협업: `main`에 직접 작업하지 않는다. 기능별 브랜치 → PR → 리뷰 → merge. v0는 `v0/...` 브랜치에 올리고 Publish로 main에 바로 반영하지 않는다(D-17). Claude Code로도 작업한다.

## 현재 구현 상태 (코드로 확인한 것)

**동작하고 Supabase에 저장된다**
- 계정: 이메일 회원가입(이메일 인증), 로그인, 로그아웃. 로그인하지 않으면 `/login`, `/signup`, `/auth/callback` 외의 화면은 로그인 화면으로 보낸다(`proxy.ts`). 학습 데이터는 아직 계정별로 저장되지 않는다

**동작하지만 브라우저 메모리에만 있다 (새로고침하면 시드 데이터로 돌아간다)**
- 페이지/그룹 트리: 생성, 이름 변경, 복제, 삭제, 하위 그룹, 드래그 앤 드롭 이동
- 페이지 템플릿 2종(학습 노트, 빈 페이지)과 학습 기록 추가/수정/삭제
- 구조화된 학습 노트 본문(핵심 개념, 헷갈린 점)과 복습 모드
- 본문 첨부(이미지, PDF, 기타 파일)와 그림 블록(펜, 형광펜, 지우개)
- 학습 계획 추가/삭제
- 과목 페이지(`/subject/[id]`): 요약, 페이지 목록, 이 과목의 학습 계획. 그룹은 폴더/과목을 고르고 바꿀 수 있다
- Home(오늘의 우선 학습, 복습이 필요한 학습, 나의 학습 상태, 오늘의 기록, 이번 주 학습 통계)과 학습 분석의 모든 위젯: 실제 페이지와 학습 기록에서 계산한다(`lib/study-stats.ts`)

**동작하고 localStorage에 저장된다**
- 전역 학습 세션 타이머 (키: `studyhaeyo:study-session`)

**정적 더미 데이터를 그대로 보여준다 (실제 데이터와 연결 안 됨)**
- Home의 오늘의 체크리스트

**UI 목업**
- AI 학습 도구(요약하기, 문제 생성하기). 실제 AI는 연결되어 있지 않다.

**아직 없다**
- 학습 데이터(페이지, 기록, 계획, 첨부)의 DB 저장, 실제 AI 연동. 학습 데이터 테이블은 PR #11에서 설계 중이다.
- 퀴즈: 기존 OX 채점 작업은 폐기하고 새로 설계한다.

자세한 구조와 규칙은 `DATA_MODEL.md`, 왜 이렇게 됐는지는 `DECISIONS.md`를 본다.
