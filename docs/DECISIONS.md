# 결정 기록

무엇을 정했는지, 왜 정했는지, 무엇을 버렸는지를 적는다. 새 결정은 맨 아래에 번호를 이어 붙인다.
한 항목은 3~5줄이면 충분하다. 버린 방향은 "폐기"로 표시해서 같은 시도를 반복하지 않게 한다.

작성 시작: 2026-10-12

---

### D-01. 학습 기록은 페이지에 딸린 데이터다 (D-24로 바뀜: 페이지 또는 과목)
학습 기록을 별도 페이지 타입이나 사이드바 트리 노드로 만들지 않는다. 한 페이지에 기록이 여러 개 쌓이는 구조다.
**이유**: Home과 학습 분석이 같은 페이지/기록 데이터를 공유해야 하고, 페이지가 학습의 중심이어야 한다.

### D-02. 복습과 AI는 페이지 타입이 아니다
복습은 "기존 페이지로 돌아가 다시 공부하는 행동", AI는 "열려 있는 페이지에서 쓰는 도구"다.
"+ 새 페이지"에는 복습하기, 문제 풀기, AI 도구, 학습 분석을 넣지 않는다.

### D-03. 페이지 트리는 깊이를 고정하지 않는다
그룹과 페이지를 자유롭게 중첩한다. 예시 데이터의 4단계는 예시일 뿐이다. 페이지 아래 그룹/페이지, 드래그 앤 드롭 이동을 지원한다.

### D-04. 페이지 종류는 템플릿 레지스트리로 관리한다
페이지 종류마다 `if` 분기를 늘리지 않고, `lib/templates.ts`의 배열에 템플릿을 추가하는 방식으로 확장한다.
D-23 이후 템플릿은 "새 페이지의 시작 블록"만 정한다(본문 컴포넌트를 템플릿마다 두지 않는다).

### D-05. 학습 기능이 켜지면 모든 페이지가 같은 속성/기록/AI 도구를 가진다 (D-30으로 바뀜: 켜고 끄기 없이 모든 노트)
**폐기**: 속성 패널(이해도, 학습 시간 등)을 학습 노트에만 허용하는 방식. 데이터는 학습 기록에서 어차피 계산되는데 한쪽에만 보여주는 "가짜 차이"였고, 빈 페이지 사용자가 자기 데이터를 못 보는 문제가 있었다.

### D-06. 학습 노트와 빈 페이지의 진짜 차이는 "시스템이 내용을 이해하는가"다 (D-23으로 대체)
D-23 이후 구조는 페이지 종류가 아니라 블록에 있다: 핵심 개념/헷갈린 점 블록이 있으면 어느 페이지든 복습 카드와 헷갈린 점 추적이 된다. 아래는 당시 기록.
학습 노트는 본문이 구조화(핵심 개념, 헷갈린 점)되어 있어서 시스템이 내용을 안다. 그래서 복습 모드, 헷갈린 점 해결 추적, Home 복습 후보, 세션 타이머 자동 추적이 학습 노트(`locked-on`)에서만 동작한다. 빈 페이지는 자유 본문이라 시스템이 내용을 모른다.
**이유**: 정보량이나 겉모습이 아니라 "구조가 있어야만 가능한 기능"으로 구분해야 둘이 다른 도구로 느껴진다.

### D-07. 학습 노트 2컬럼 레이아웃은 폐기했다
**폐기**: 학습 노트만 좌측 속성 패널 + 우측 본문의 2컬럼으로 만든 시도. UI 통일감만 깨지고 기능 차이는 만들지 못했다. 지금은 모든 페이지가 같은 1컬럼 틀을 쓴다.
같은 이유로 색 틴트나 아이콘만으로 차별화하는 접근도 효과가 없었다(차이가 페이지를 열었을 때 보이지 않아서).

### D-08. 복습 추천은 학습 노트만, 누적 통계는 모든 페이지 (D-23으로 대체: 학습 기능이 켜진 모든 페이지가 후보)
Home의 복습 추천("오늘 할 일"의 복습할 노트)은 `locked-on` 페이지만 후보로 삼는다. 학습 분석의 총 학습 시간, 기록 수, 평균 이해도는 빈 페이지의 기록도 포함한다.
**이유**: 실제로 공부한 시간은 사실이므로 통계에는 넣고, "복습하라"는 능동 추천은 학습 노트로 약속한 페이지에서만 한다.

### D-09. 학습 시간은 홈의 전역 세션 타이머로 자동 기록한다
페이지마다 타이머를 두지 않는다. 홈에서 세션을 켜 두면 방문한 학습 노트별로 시간이 자동으로 나뉜다. 빈 페이지 방문은 기록하지 않는다.
**이유**: 한 번 앉아서 여러 과목을 오가는 실제 공부 패턴에 맞고, 페이지마다 버튼을 누르는 걸 잊을 일이 없다. 수동 입력(기록 폼)도 대안으로 남겨 둔다.

### D-10. 세션 시간 중복 집계는 "기록이 있으면 기록이 우선"으로 한다
**폐기**: 요약 모달 버튼으로 만든 기록만 "기록됨"으로 표시하던 방식. 복습 완료나 직접 추가에서는 같은 시간이 두 번 집계됐다.
지금은 그 세션 동안 그 페이지에 기록이 하나라도 있으면 측정 시간을 빼고 기록값만 쓴다. 사용자가 미리 채워진 시간을 줄이면 그 값이 확정값이다.

### D-11. 비정상 종료된 구간은 "마지막 활동 시각"에 닫는다
탭을 닫거나 자리를 비운 시간이 학습 시간에 들어가면 안 된다. 30초마다 마지막 활동 시각을 저장하고, 다시 열릴 때 그 시각으로 닫는다. 30분 이상 활동이 없었으면 세션도 그 시각에 자동 종료한다.

### D-12. hydration 오류는 서버 스냅샷을 고정해서 푼다
현재 날짜 같은 브라우저 값은 서버 스냅샷을 null로 두고 마운트 이후에만 읽는다(`hooks/use-today.ts`).
**하지 않는 것**: `suppressHydrationWarning`으로 경고를 숨기기, 임의의 고정 날짜 넣기, 렌더 중 `new Date()` 직접 사용.

### D-13. AI 기능은 UI 목업이고 실제 AI는 후순위다 (D-22로 대체)
요약하기/문제 생성하기는 화면만 있다. 실제로 학습 데이터를 분석하거나 추천하는 것처럼 표현하지 않는다. 실제 AI 연동은 DB와 데이터 연결 이후 단계다.

### D-14. 협업은 repo 문서 + PR로 한다
**폐기**: 변경이 생길 때마다 긴 설명 프롬프트를 상대에게 붙여넣는 방식(보내는 순간부터 낡는다).
`main`에 직접 작업하지 않고 기능별 브랜치 → PR → 리뷰 → merge. 공유할 내용은 `docs/`와 PR 설명에 둔다. 데이터 구조를 바꿀 때는 구현 전에 문서만 바꾼 PR로 먼저 합의한다.

### D-15. 첨부는 본문 블록으로, 페이지 메뉴는 한 컴포넌트로 공유한다
파일과 이미지는 별도 목록이 아니라 본문 블록(image, file)으로 넣는다. 첨부 진입은 본문 버튼이 아니라 페이지 헤더 ⋯ 메뉴의 "파일 첨부"(그리고 드래그 앤 드롭, 붙여넣기)다. 사이드바와 페이지 헤더의 ⋯ 메뉴는 같은 컴포넌트(PageActionsMenu)를 쓴다.
**이유**: 첨부가 글 사이에 자연스럽게 들어가고, 같은 동작을 두 곳에 복사하면 서로 어긋나기 때문이다.

### D-16. 그림은 이미지가 아니라 획 데이터로 저장한다
그림 블록은 획(좌표 목록, 도구, 색, 굵기)을 블록 너비 기준 비율 좌표로 저장한다.
**이유**: 화면 크기가 바뀌어도 모양이 유지되고, 획 단위로 지우거나 되돌릴 수 있으며, 이미지보다 용량이 작다.

### D-17. v0의 Publish로 main에 바로 합치지 않는다
**폐기**: v0에서 Publish를 눌러 main에 바로 반영하던 방식. 검사 없이 main이 바뀌어서 2026-10-17에 main의 빌드가 깨졌다(서버 컴포넌트가 클라이언트 저장소를 import).
모든 변경은 브랜치 → PR → PR의 Vercel 미리보기 빌드가 Ready인지 확인 → merge 순서로 한다.

### D-18. 인증은 Supabase Auth 이메일 로그인으로 한다
이메일 + 비밀번호로 가입하고, 이메일 인증을 거친다. 세션은 `@supabase/ssr` 쿠키로 유지하고, 로그인하지 않은 요청은 `proxy.ts`가 `/login?next=...`로 보낸다(PR #15). 소셜 로그인과 비밀번호 찾기는 아직 없다.
화면은 Supabase를 직접 부르지 않고 `lib/auth.ts`의 함수(`signIn`, `signUp`, `signOut`, `useCurrentUser`)만 부른다(PR #14). `lib/workspace.ts`와 같은 원칙이다.
**이유**: DB도 Supabase로 가므로 같은 사용자 id(`auth.users`)로 RLS를 걸 수 있다. 별도 서버 없이 가입/인증 메일/세션 갱신이 해결된다.

### D-19. merge는 Vercel 프로젝트 주인(이재윤)이 누른다
Vercel 프로젝트는 이재윤의 Hobby(무료) 계정에 있다. Hobby는 비공개 저장소에서 계정 주인이 만든 커밋만 배포하고, 다른 사람의 커밋은 "Deployment was blocked"가 된다. merge 커밋의 작성자는 merge 버튼을 누른 사람이다.
2026-10-20~21에 김준혁이 merge한 PR #16~#22가 모두 배포되지 않았고, 대시보드의 Redeploy도 같은 이유로 막혔다. 이재윤이 #12를 merge해서 그 시점의 main 전체가 배포됐다.
그래서 리뷰와 승인은 둘 다 하고, merge 버튼은 이재윤이 누른다.
**대안(지금은 안 함)**: 저장소를 공개로 바꾸기(누가 merge해도 배포됨), Vercel Pro로 올리고 팀원 추가(유료).

### D-20. 체크리스트의 못 끝낸 할 일은 다음 날로 넘어온다
오늘의 체크리스트는 오늘 할 일 + 지난날 못 끝낸 할 일을 보여준다. 끝낸 할 일은 끝낸 날에만 보인다. 페이지·계획과는 연결하지 않는다(R10).
**이유**: 공부할 일은 하루에 못 끝내는 경우가 많고, 넘어오지 않으면 매일 다시 적어야 한다. 처음 기획서의 "학습·과제 수행 여부 체크"를 가장 작은 형태로 만든다.
**하지 않은 것**: 날짜별 체크리스트 기록 보기, 반복 할 일, 페이지·계획 연결.

### D-21. Home은 "오늘 할 일" 한 카드로 시작한다
복습할 노트, 진행 중인 계획, 체크리스트를 홈 맨 위의 한 카드로 모은다(R11). 전에는 오늘의 우선 학습, 복습 목록, 체크리스트가 따로 있었고 계획은 홈에 없었다.
**이유**: "학습 OS"는 기능을 나열하는 것이 아니라 오늘 무엇을 할지 한곳에서 정해 주는 것이다. 계획은 진도가 보여야 행동으로 이어진다.
**하지 않은 것**: 계획에 숫자 목표(목표 시간)를 저장해 진도율을 계산하기. DB 구조 변경이 필요해 발표 뒤에 정한다.

### D-22. AI 학습 도우미는 Claude API를 서버 경로에서 부른다
학습 페이지 아래의 채팅에서 페이지 내용(제목, 본문 또는 학습 노트, 최근 학습 기록 3개)을 맥락으로 Claude에게 묻는다. 빠른 질문(요약, 정리 노트, 확인 문제, 헷갈린 점 설명)과 자유 질문을 지원하고, 답은 "AI 정리" 제목과 함께 본문 끝에 블록으로 추가할 수 있다.
- 키는 서버 전용 환경 변수 `ANTHROPIC_API_KEY`, 모델은 `AI_MODEL`(기본 `claude-sonnet-5-5`). 로그인한 사용자만 부를 수 있고, 한 사용자당 분당 10회(서버 인스턴스별 대략적 제한)
- 대화 기록은 저장하지 않는다(페이지를 떠나면 사라진다). 그림과 PDF 위 필기는 AI에 넘기지 않는다
- PDF(2026-10-23 추가): 채팅 위 "PDF도 같이 보기"에서 고른 PDF(최대 2개, 합쳐 50쪽)를 질문과 함께 보낸다. 브라우저는 Storage 경로만 보내고, 서버가 사용자 세션으로 Storage에서 받아(RLS로 본인 파일만) Claude에 document 블록으로 넘긴다. Storage에 저장된 PDF만 고를 수 있다. 매 질문마다 PDF를 다시 보내므로 첫 메시지에 붙이고 prompt cache를 건다
**이유**: 팀이 Claude를 쓰기로 했고(2026-10-22), 키를 브라우저에 노출하지 않으려면 서버를 거쳐야 한다. 정해진 버튼 두 개(요약, 문제)보다 사용자가 원하는 정리·문제를 직접 요청하는 쪽이 학습 도구로 쓸모가 크다.
**왜 50쪽인가**: Claude는 한 요청에 100쪽(32MB)까지 받지만 쪽당 1,500~3,000토큰이라 비용이 크다. 강의 자료 한 단원 정도를 기준으로 잡았다.
**2026-10-24 변경 (퀴즈를 AI에 합침)**:
- 페이지 아래 채팅 → 어느 페이지에서나 헤더 [AI]로 여는 오른쪽 패널(휴대폰은 전체 화면). 학습 기능이 꺼진 페이지에서도 쓴다
- 자료가 없으면(본문 비어 있고 PDF 없음) 제목·질문을 주제로 일반 지식으로 답하고, 첫 줄에 "자료 없이 만든 내용"이라고 밝힌다
- 문제를 만들면 "## 정답과 해설"은 화면에서 접어 둔다. 사용자가 채팅으로 답을 보내면 채점하고, 마지막 줄 "점수: 4/5"를 화면이 읽어 [기록으로 남기기](빠른 기록 창, 이해도는 점수 비율로 미리 채움)와 [헷갈린 점에 추가](답의 "## 헷갈린 점" 목록 → 헷갈린 점 블록)를 띄운다
- 정리 답의 "## 핵심 개념" 목록은 본문에 넣을 때 개념 블록(복습 카드)이 된다
- 새 페이지 템플릿 "AI로 시작하기": 제목을 주제로 삼아 패널이 열린 채로 시작한다(`?ai=1`)
- **폐기**: 별도 퀴즈 기능. 문제 생성과 채점을 대화 하나로 한다(프롬프트 규칙은 `app/api/ai/chat/route.ts`의 SYSTEM)
**다음 단계**: 손글씨 답(PDF 위 필기) 채점, 이미지 첨부 넘기기.

### D-23. 모든 페이지는 빈 페이지 + 블록이고, 템플릿은 시작 블록만 정한다 (D-30으로 일부 바뀜)
학습 노트의 고정 섹션(오늘 배운 내용 / 핵심 개념 / 헷갈린 점)을 블록으로 바꿨다. 핵심 개념(`concept`)과 헷갈린 점(`confusion`)은 블록 종류이고, 템플릿(학습 노트 · 강의 노트 · 오답 노트 · 시험 정리)은 이 블록들로 미리 채운 시작점이다. 학습 기능은 모든 페이지에서 켜고 끌 수 있다.
**이유**: 노션처럼 "빈 페이지에 필요한 것만 더한다"는 방향. 고정 섹션은 강의 필기·오답 정리처럼 다른 모양의 공부를 담지 못했고, 학습 노트와 빈 페이지가 따로 노는 두 가지 편집기였다.
**DB를 바꾸지 않은 방법**: `template_id`는 `"study-note"`/`"blank"`만 쓰고, 옛 `note` 컬럼은 읽어서 블록으로 보여주기만 한다(쓰지 않음). 발표 직전이라 이전 빌드로 되돌려도 데이터가 그대로 보이게 하려는 것.
**폐기**: `studyMode: "locked-on"`(학습 노트는 학습 기능을 끌 수 없음), 템플릿마다 본문 컴포넌트를 두는 방식(`StudyNoteBody`/`FreeBody`).

### D-24. 학습 기록은 페이지 또는 과목에 붙는다 (빠른 기록)
페이지 없이 공부한 것(학교 수업, 문제집)도 기록할 수 있게 `study_records`에 `subject_id`를 더하고 `page_id`를 비울 수 있게 했다. 기록은 어디서나 [+ 기록]으로 남긴다(사이드바, 휴대폰 상단, 과목 화면, 타이머 요약). 페이지는 고르면 붙고, 안 고르면 과목에 남는다. 나중에 과목 기록을 고치며 페이지에 연결할 수 있다.
**이유**: 기록하려고 페이지부터 만들어야 하는 순서가 실제 공부(수업 → 나중에 정리)와 반대였다. 기록이 먼저고 노트는 필요할 때 만든다.
**과목을 페이지 기록에 저장하지 않는 이유**: 페이지를 옮기면 과목이 바뀌어야 하는데, 저장해 두면 두 값이 어긋난다.
**기록 창은 과목 먼저, 노트는 선택**(2026-10-24 재검토): 과목과 페이지를 같은 무게로 나란히 두니 기록이 어디로 가는지 헷갈렸다. 기록의 주인은 과목이고, 노트 연결은 "복습할 거리가 있을 때"만 한다(연결해야 복습일이 생긴다). 그래서 과목은 필수, 노트는 접힌 선택 칸이고, 저장 전에 어디에 들어가는지 한 줄로 보여준다. 과목 화면은 노트 기록과 과목 기록을 한 목록("학습 기록")으로 보여준다. DB 준비 전에는 저장할 수 없는 버튼을 보여주고 막는 대신 숨긴다.
**외부 학습 기록은 아무것도 만들지 않고 남긴다**(2026-10-25 재검토, 이재윤): 프로그램 밖에서 공부한 것(수업, 문제집)을 기록하려고 과목이나 노트를 새로 만들어야 하는 건 어색하다. 그래서 과목 필수를 버린다.
- 기록 창은 "무엇을 했나요"(글)가 맨 위, 그다음 날짜 · 시간 · 이해도. 과목과 노트는 **이미 있으면 골라 연결하는 선택 칸**이고, 기록 창에서 새로 만들게 하지 않는다("+ 새 과목" 없음)
- 기록은 노트 · 과목 · 둘 다 없음 중 하나. 노트에 연결된 기록만 복습일을 만든다. 과목이 없는 기록은 통계에서 "외부 학습"으로 묶는다
- 모든 기록이 모이는 "학습 기록" 화면(사이드바)을 둔다. 노트도 과목도 없는 기록은 여기서 고치고 지우고, 나중에 노트에 연결한다. 과목 화면은 그 과목으로 거른 목록이다
- DB: "노트나 과목 중 하나는 있어야 한다" check를 빼고, 과목을 지워도 기록은 남긴다(`subject_id` on delete set null). SQL 초안(`20261024_subject_records.sql`)을 이 방향으로 고쳤다
- **구현은 발표(10/26) 뒤**: 지금 코드는 여전히 과목 필수이고, DB가 없어 이 기능 전체가 숨겨져 있다
**폐기**: D-01의 "기록은 페이지 하단에만" 전제. 위의 "과목 필수"(10/24).

**폐기**: 오른쪽 학습 패널(본문 폭이 줄어듦, A안), 노트 탭(기록을 보려면 한 번 더 눌러야 함, B안), 제목 아래 요약 줄(C안), 속성을 제목 위로(D안), 학습 분석 안의 "기록 전체 보기"(기록을 고치고 연결할 곳이 통계 화면이 됨).

### D-30. 노트 종류가 노트의 모양을 정하고, 학습 기능 켜기·끄기와 속성 창은 없앤다 (학습 노트는 D-33으로 없앰)
- **학습 기능 켜기·끄기를 없앤다**: 모든 노트가 학습 기록 · 복습 · 세션 시간 · AI를 가진다. `studyEnabled`는 읽기만 한다
- **종류 칩**: 위쪽 바의 [속성] 자리에 그 노트의 종류(학습 · 강의 · 오답 · 시험 · 빈 노트)를 보여주고, 눌러서 바꾼다. 메뉴에는 종류만 둔다. 바꿔도 본문은 지우지 않는다. 본문이 비어 있으면 새 노트의 종류 버튼과 똑같이 그 종류의 시작 칸으로 채운다(2026-11-07: 같은 빈 노트에서 칩과 버튼이 서로 다른 노트를 만들었다)
- **종류별 값은 쓰는 곳에서**: 시험일 · 범위는 시험 정리 맨 위, 문제 출처는 오답 노트 맨 위(시험지 머리), 강의 자료 · 주차는 강의 노트 맨 위. 시험 정리는 같은 과목 노트를 범위로 미리 채운다
- **노트 끝**: ~~학습 기록 요약 한 줄과 [기록 남기기] 하나, 접힌 기록 목록,~~ 들어간 곳(시험 범위 · 진행 중인 계획), 태그 (D-36: 기록은 위쪽 바 [기록] 창으로)
- **기록 창**: 이해도는 숫자와 말로 고른다. 노트 안에서 열면 "어디에"를 묻지 않는다. 어려웠던 점 · 다음에 할 일 칸 대신 [헷갈린 점을 노트에 추가] · [내일 할 일에 추가]
- **같은 동작은 같은 이름**: 오답 노트 "다시 풀기", 개념 카드가 있으면 "카드 복습", 없으면 "복습하기"(홈 · 상태 칩 · 시험 범위)
- **사이드바**: 노트 줄에 종류 아이콘, 복습할 노트는 작은 점, 글자는 시험 D-day만
- **새 노트**: 종류 4개를 그 종류의 모양을 작게 그린 칸으로 보여준다. 고르지 않고 쓰면 빈 노트
- **다음 PR(설계안 "노트 개편 설계안", 아직 만들지 않음)**: 종류마다 중심 블록(오답=채점된 시험지, 시험=일력과 "시험 전에 다시 볼 것", 강의=PDF 쪽 옆 필기, 학습=개념 카드), 다시 풀기 · 카드 복습이 끝나면 자동 기록
**이유**: 템플릿이 시작 블록만 달라 열었을 때 차이가 안 보였고(D-07과 같은 문제), "학습 기능 추가"는 템플릿과 같은 질문을 한 번 더 했으며 꺼진 노트는 타이머 시간도 안 쌓였다. 속성 창은 입력 · 계산 · 연결이 섞여 열 이유가 없었다(2026-11-02 이재윤, 시안 H~K와 사용자 장면 점검 후).
**폐기**: 학습 기능 켜기 · 끄기, 속성 창(D-28), 종류 칩 메뉴 안의 위치 · 태그, 활동이 끝난 뒤 확인 창으로 기록(복습했는데도 "지남"으로 남을 수 있음), 노트 탭(브라우저 탭과 역할이 겹쳐 보류), UI UX Pro Max의 디자인 시스템 추천(어린이용 스타일 · 한글 없는 글꼴).

### D-31. 주된 길 하나: 계획 → 오늘 할 노트 → 공부 → 확인 문제 → 이해도 → 돌아보기
- **주된 길**: 학습 계획에서 공부할 노트를 고르면 홈 "오늘 할 일"에 나오고, 공부를 마칠 때 확인 문제로 이해도를 재고, 그 결과(이해도 · 다음 복습 · 계획 진도)를 학습 분석에서 돌아본 뒤 다음 계획으로 이어진다. 각 화면은 이 길의 다음 화면을 가리킨다. 다른 기능(체크리스트 · 달력 · AI 질문 등)은 이 길을 돕는 곁길이다
- **이해도는 문제로 잰다**: 공부를 마친 뒤 그날 공부한 양에 맞춘 개수로, 난이도(하 · 중 · 상)를 섞거나 골라서 낸다. 세부 수치와 저장할 칸은 데이터 변경 설계에서 정한다(아직 없음)
- **학습 계획은 대상을 고른다**: 사용자나 AI가 폴더 · 과목 · 노트를 골라 세우고, 끝낸 노트 · 과목은 계획에서 저절로 빠진다(아직 없음, 데이터 변경 설계에서)
- **한 목록은 한 곳에서 끝까지**: 홈 복습 목록은 3개 뒤를 그 자리에서 펼친다(학습 분석으로 보내지 않음). 일주일 안 시험의 범위 노트가 맨 위
- **같은 것은 같은 말로**: 이해도 1~5는 어디서나 "처음 본 듯 · 많이 헷갈림 · 대충 앎 · 거의 앎 · 설명 가능"
- **휴대폰에서도 같은 일을**: 노트 ⋯ 메뉴의 [옮기기]로 끌지 않고 과목 · 폴더로 옮긴다. 새 그룹은 과목이 기본, 사이드바 [+]는 지금 보고 있는 곳에 만든다
**이유**: 교수님 피드백(2026-11-02): 학습 → 기록 → 분석 → 피드백이 제대로 이어지는가, 그리고 난이도가 다른 문제에 모두 같은 점수를 주면 이해도 측정이 치우친다는 점. 점검해 보니 기능은 있지만 화면 사이가 끊겨 있었다(계획은 고칠 수 없고 시간만 셈, 달력 · 과목 이해도는 막다른 곳, 복습 목록 4번째부터는 학습 분석에 가야 보임, 이해도 말이 세 벌). 2026-11-03 이재윤.
**폐기**: 문제 개수 고정(공부한 양에 맞춘다), 공부 전에 푸는 문제(이해도는 공부한 뒤에 잰다), 학습 분석 안에 기록 목록(D-28에서 이미 폐기), AI를 모든 화면에 넣기. **보류**: 많은 사용자가 어려워한 내용을 미리 알려주기(교수님 제안, 할 일이 많아 나중에 정함), 디자인 다듬기.

### D-32. 확인 문제는 난이도를 섞어 내고, 이해도는 사다리로 읽는다
- **섞어서 잰다**: 이해도를 잴 때는 하(용어와 정의) · 중(예제에 적용) · 상(비교하고 이유 설명)을 40 · 40 · 20으로 섞는다(상 최소 1). 한 난이도로만 내면 같은 100점이라도 뜻이 달라서 이해도끼리 비교할 수 없다. 한 난이도만 고르는 것은 연습이고, 그 범위 안에서만 이해도를 정한다(하 1~3, 중 2~4, 상 3~5)
- **사다리**: 아래 단계부터 통과해야 위로 올라간다(상을 운으로 맞혀도 하를 틀리면 5가 아니다). 통과는 다 맞히거나, 그 단계 문제가 3개 이상이면 1개까지 틀림. 막힌 단계로 "중에서 막혔어요. 예제에 적용해 보는 연습이 필요해요"처럼 바로 알려 준다(AI가 아니라 규칙)
- **이름은 하 · 중 · 상**: 누구나 바로 알고, 쉬운 단계부터 올라가는 사다리라 난이도로 읽혀도 맞다(2026-11-06 이재윤)
- **개수는 노트 양에 맞춘다**: 핵심 개념 1개에 1문제 + 안 풀린 헷갈린 점 최대 2, 3~10개. "지난 문제 이후 새로 공부한 양"으로 세는 것은 마지막 문제 시각을 저장해야 해서 데이터 변경 뒤에 한다(아직 없음)
- **틀린 문제는 오답 노트로**: 채점 뒤 [틀린 문제를 오답 노트로]가 같은 과목에 오답 노트를 만들고, 기록이 없어도 틀린 문제가 있는 오답 노트는 다음 날 홈의 복습할 노트(다시 풀기)에 나온다
- 먼저 노트의 AI 패널에서 한다. 공부를 마칠 때(학습 종료) 바로 여는 것은 데이터 변경 뒤(할 일 순서 5번)
**이유**: 교수님 피드백(2026-11-02): 문제로 이해도를 잴 때 난이도가 다른 문제에 모두 같은 점수를 주면 이해도 측정이 치우친다. 그래서 맞힌 수를 더하지 않고, 아래 단계를 통과해야 위로 올라가게 했다. 처음 안은 단계마다 80% 통과였지만, 한 단계 문제가 보통 1~4개라 사실상 "다 맞혀야 통과"여서 바꿨다(2026-11-04 이재윤, 써 보고 마음에 안 들면 고친다).
**폐기**: 문제 개수 고정(5개), 맞힌 비율만으로 이해도 정하기(난이도 편차), 단계마다 80% 통과, 단계 이름을 기억 · 적용 · 비교로 바꾸기(2026-11-06 개편 검토에서 "하 · 중 · 상이 난이도로만 읽힌다"는 이유로 냈지만, "기억 문제"가 무엇인지 오히려 불분명했다. 이재윤).

### D-33. 학습 노트를 빈 노트로 합친다
노트 종류는 강의 노트 · 오답 노트 · 시험 정리 · 빈 노트 넷이다. 학습 노트 칸과 그 시작 제목(오늘 배운 내용 · 핵심 개념 · 헷갈린 점)은 없앤다.
- **종류는 빈 노트에 없는 기능이 있어야 종류다**: 강의 노트(강의 PDF 나란히 보기 · AI로 핵심 개념 뽑기 · 주차), 오답 노트(문제마다 맞음/틀림 · 틀린 문제만 다시 풀기 · 다 맞히면 복습 끝), 시험 정리(시험일 · 범위 · D-day · 범위 노트의 복습을 시험 전으로 당기기)
- **있던 학습 노트**: 내용은 그대로, 빈 노트로 보인다. DB는 바꾸지 않는다(`template_id`가 `"study-note"`여도 종류가 없으면 빈 노트, 저장된 `props.kind: "note"`도 빈 노트로 읽는다)
- **핵심 개념 찾기**: 학습 노트가 보여 주던 핵심 개념 칸은 빈 본문 안내("/ 를 누르면 제목, 목록, 핵심 개념(복습 카드) 같은 메뉴가 나와요")로 찾게 한다
- **`props` 칸이 생기기 전에는 종류 칸을 보이지 않는다**: 종류는 `props`에 저장되므로, 그 전에 누르면 이름은 학습 노트이고 기능은 없는 노트가 생겼다. 새 노트에는 [AI로 채우기]만, 기록에서 만들 때는 "새 노트로 만들기"만 보인다(종류 칩 메뉴는 원래대로 "데이터 준비가 끝나면 쓸 수 있어요")
**이유**: 2026-11-07 종류마다 빈 노트와 기능을 비교해 보니 학습 노트에만 있는 기능이 없었다. 개념 카드 복습 · 학습 기록 · AI · 확인 문제는 모든 노트에 있다. 차이 없는 선택지는 고를 것만 늘린다(이재윤).
**폐기**: 학습 노트만의 개념 카드 화면 만들기(D-30 "다음 PR"의 학습=개념 카드. 발표 전 일정에 비해 크고, 모든 노트에서 되는 카드 복습을 한 종류에 묶게 된다), 시작 모양만 다른 채로 두기(종류마다 기능이 다르다는 설명과 맞지 않는다).

### D-34. 복습은 노트 안에서, 답을 가리고 다시 읽는다 (개편 3b-1)
[복습하기 · 다시 풀기 · 복습해 보기]를 누르면 그 노트가 쓴 모양 그대로 열리고(`?mode=review`), 답이 있던 자리만 회색 줄로 가려진다. 떠올려 보고 회색 줄을 눌러 펼친 뒤 그 줄 끝의 작은 표시(알았음 · 헷갈림 · 몰랐음)를 고르고, 다 고르면 위쪽 바의 [복습 마치기]로 기록 하나를 남긴다.
- **정해진 틀 없이 아무 노트나**(2026-11-07 이재윤, "틀에 맞게 써야 기능이 되는 것처럼 보인다"): 무엇을 가릴지는 앱이 요구하는 칸이 아니라 사람들이 노션에 이미 쓰는 방식에서 읽는다. 소제목은 그 아래 글을, 토글은 안의 내용을, 핵심 개념은 뜻을 가린다(최대 12곳). 셋 다 없는 줄글 노트는 문단마다 첫 단어(또는 `용어:`의 용어)만 두고 나머지를 가린다. 오답 노트는 아직 틀린 문제를 접어 두고 펼친 뒤 원래 있던 맞힘 · 틀림을 고른다. 가릴 것이 하나도 없으면 노트를 다시 읽고 이해도 1~5를 직접 고른다
- 기록이 없는 노트에도 가릴 곳이 있으면 위쪽 바에 [복습해 보기]가 나온다
- **화면에 하 · 중 · 상이나 "카드" 같은 말을 쓰지 않는다**. 이해도는 사다리(D-32)로 안에서 계산한다: 고른 것 중 하나라도 알았거나 헷갈렸으면 2(많이 헷갈림), 가장 낮은 단계를 통과하면 3. 노트 안에는 답 쓰는 칸을 두지 않으므로(입력 양식이 된다) 여기서는 3이 끝이고, 4 · 5는 AI 창의 확인 문제에 답을 써서 맞힐 때 오른다(D-32의 "4 · 5는 써 본 답으로만" 그대로)
- **조용하게**: 안내는 제목 아래 한 줄, 결과도 한 줄. 상자 · 카드 · 큰 버튼을 쓰지 않는다. 핵심 개념과 헷갈린 점도 평소에 카드가 아니라 작은 표시(열쇠 · 물음표)가 붙은 보통 줄이다(D-28의 카드 줄을 바꿈)
- **마친 뒤**: 제목 아래에 결과 한 줄(이해도 변화, 몇 곳 중 몇 곳 알았나, 다음 복습일 — 시험 범위면 시험 전날로 당김)과 [다음 노트: …](오늘 복습할 다른 노트), [기록 되돌리기]. 오늘 할 일은 목록 그대로 두고, 노트에서 노트로 이어서 복습한다
- **그만두기**: 다 고르기 전에 나가면 기록하지 않는다(지금 기록은 이해도가 꼭 있어야 해서 "시간만" 남길 수 없다). 오답 노트 문제의 맞힘 · 틀림은 누른 그때 노트에 남는다(원래 동작)
- **데스크탑이 메인**(2026-11-07 이재윤): 노션처럼 사이드바와 노트 그대로. 휴대폰은 같은 화면을 줄여서 쓴다(표시는 글 아래로)
**이유**: 이해도를 정하는 길이 카드 복습 · 다시 풀기 · AI 채점 · 직접 고르기로 넷이라 같은 노트가 길마다 다른 값을 얻었다(개편 통합 검토, 11/6). 그래서 판정과 기록을 하나로 묶는다. 처음에는 문항을 하나씩 넘기는 별도 복습 화면(`/review`)으로 만들었는데, "카드 · 하" 꼬리표와 큰 버튼으로 하나씩 넘기는 모습이 노션식 자유로운 노트가 아니라 듀오링고 같은 앱 학습처럼 보였다(2026-11-07 이재윤, D-25의 "재촉하지 않는다"와도 어긋남). 복습도 사용자가 짠 노트 모양 안에서 한다. 두 번째 안은 핵심 개념 칸이 있어야 복습이 되는 것처럼 보였고 카드와 상자가 많아 노트가 못생겨 보였다(같은 날 이재윤).
**폐기**: 문항을 하나씩 넘기는 별도 복습 화면(`/review`, PR #78 첫 안), 핵심 개념 · 소제목 칸이 있어야만 가리던 것과 카드로 된 핵심 개념 · 헷갈린 점(PR #78 둘째 안), 노트 본문을 카드 목록으로 바꾸던 예전 복습 모드(`study-note-review.tsx`), 헷갈려요로 고른 개념을 헷갈린 점 블록으로 자동 추가하던 것, 홈 학습 세션의 "공부할 과목" 고르기(노트 시간은 노트별로 자동으로 모이고, 노트 밖 시간은 세션을 마칠 때 요약에서 과목을 고른다).
**아직**: 질문 블록과 헷갈린 점의 정리한 답(가릴 곳이 더 생긴다), 하루 상한 · 홈 개편 · AI 창의 확인 문제 정리(3b-2), 다 고르지 않고 나간 복습의 시간 기록.

### D-35. 노트 종류마다 모양이 다르다: 강의 노트 = 코넬 노트, 오답 노트 = 채점된 시험지, 시험 정리 = 범위표
세 종류가 빈 노트에 소제목 몇 개만 깔린 모양이라 열어 보면 빈 노트와 차이가 없었다(2026-11-07 이재윤). 노션에서 많이 쓰는 공부 형식을 가져오되, 모양마다 복습 기능이 붙어 있어야 한다(D-07: 모양만 다른 것은 효과가 없었다). 칸은 모두 비워 둬도 된다(D-34의 "정해진 틀 없이").
- **오답 노트 = 채점된 시험지**: 문제(토글)마다 번호 위에 채점 표시(맞힘 동그라미 · 아니면 빗금), 펼치면 "내 답" 한 줄 · 정답과 풀이(토글 안 자유 글) · 틀린 이유(개념 몰라서 / 실수 / 문제 잘못 읽음 / 시간 부족, 안 골라도 되고 여러 개). 다시 풀기에서는 내 답이 보이고 정답 · 풀이만 가려진다. 위쪽 줄에 틀린 이유를 센다("개념 1 · 실수 2", 지금 노트에 있는 문제마다 한 번씩, 결과와 상관없이). 맞힌 문제는 접혀 흐리게 "눌러서 다시 보기". 맞힘 · 틀림 글자는 바탕색 없이 작게(번호의 채점 표시가 같은 것을 더 크게 말한다). 시작 칸은 빈 문제 하나
- **강의 노트 = 코넬 노트**: 단서(질문이나 키워드)는 본문 왼쪽 여백에, 단서 하나가 블록 하나(옆의 가는 세로줄로 묶는다). 줄에 마우스를 올리면 "+ 단서", 블록 메뉴에 [단서 달기]. 여백이 좁으면(PDF · AI 창을 열었거나 화면이 작으면) 단서가 블록 위로 오고 블록 메뉴로 단다. 단서가 블록보다 길면 그 줄이 단서만큼 길어진다(아래 단서와 겹치지 않게). "단서" 머리글은 단서가 하나라도 있을 때만. 시작 칸은 필기 한 줄 · 구분선 · 단서가 "요약"인 빈 줄. 복습은 단서 단 블록만 통째로 가리고 단서는 보인다. 단서가 하나도 없으면 다른 노트와 같은 규칙
- **시험 정리 = 범위표**: 일력(달 띠 + 날짜)과 D-day · 요일, 그 아래 한 줄로 상태별 수. 범위 노트마다 상태 글자와 점(다시 확인 · 미확인 · 일부 확인 · 확인됨, 확인이 필요한 것부터), 오른쪽은 [복습하기] 또는 다음 복습 날짜. 복습은 각 노트에서(범위표에서 몰아서 하지 않는다). 그 아래 **시험 전에 다시 볼 것**: 범위 노트에서 자동으로 모은다 — 아직 해결 안 한 헷갈린 점(?를 누르면 원래 노트의 해결 표시만 바뀌고 이해도 · 복습일은 그대로, [되돌리기]), 오답 노트의 아직 틀린 문제, 그 노트 가장 최근 기록의 어려웠던 점(읽기만). 범위표 순서, 노트마다 3개까지 보이고 나머지는 접힘, 항목을 누르면 노트의 그 줄로 간다. 본문 시작 칸은 "시험 당일 챙길 것"(체크 목록) 하나(손으로 쓰던 "시험 전날 다시 볼 것"은 자동 모음이 대신)
**이유**: 외부 검토(ChatGPT, 11/7~8 세 번): 오답 노트가 가장 강한 차별점, 입력 양식처럼 보이지 않게 고정 칸은 내 답 하나, 틀린 이유는 선택 · 여러 개, 같은 결과를 세 군데서 강하게 보이지 않게.
- 화면에서는 단서를 "질문"이라고 부른다(2026-11-11): "+ 질문", [질문 달기]. 새 노트 카드는 "질문을 달아"인데 노트 안은 "단서"라 같은 것이 두 이름이었고, "단서"는 코넬 노트를 아는 사람만 아는 말이었다. 코드와 이 문서의 이름은 그대로 단서(`cue`)
- AI 답을 강의 노트 본문에 넣으면 "핵심 개념"의 "용어: 설명"은 설명 한 줄 + 질문(용어)이 된다(`withCues`): AI가 쓴 내용도 필기처럼 가려져 복습된다. 오답 노트는 바꾸지 않는다(틀린 문제는 AI 창의 [오답 노트 만들기]가 이미 문제 모양으로 넣는다)
**폐기**: 강의 노트의 고정 두 칸(단서 칸이 비면 공간만 차지하고 PDF를 펴면 필기가 좁아짐), 단서 하나가 다음 단서까지 묶는 것(긴 노트에서 상관없는 줄까지 가려짐), 오답 노트의 "풀이 · 다음엔" 칸, 시험 정리의 신호등 막대와 줄마다 "다시 볼 때예요", 상단 탭 · 어두운 모드(발표 뒤로).

### D-36. 학습 기록은 노트 밖으로: 위쪽 바 [기록] 창 (D-28 · D-30의 "노트 끝 학습 기록"을 바꾼다)
기록은 노트 내용이 아니라 공부한 일의 로그인데, 노트 끝에 붙어 있어서 문서가 입력 양식처럼 보였다(2026-11-08 이재윤). "다시 볼 때예요 · 다음 복습"은 위쪽 바 · 노트 끝 · 홈에 세 번 나왔고, 시험 정리처럼 그 노트 자체를 공부하지 않는 노트에서는 "공부를 마쳤으면 기록을 남겨 보세요"가 어색했다(기록을 남기면 시험 정리가 복습할 노트로 홈에 떴다). 기록은 점점 자동으로 생긴다(노트 안 복습 마치기, AI 채점, 곧 타이머 [마치기]).
- **노트**: 제목 · 종류별 머리 · 본문, 끝에는 들어간 곳 · 태그만(얇은 줄)
- **위쪽 바 [기록]**: 이 노트의 기록 창. 이해도 변화 · 총 시간 · 다음 복습 한 줄, 최근 기록 3개(누르면 학습 기록 화면의 그 노트로 거른 목록), [+ 기록 남기기](원래 기록 창), [학습 기록에서 모두 보기]. 휴대폰은 아래에서 올라오는 창, 버튼 글자 "기록"은 숨기지 않는다
- **기록 고치기 · 지우기**: 학습 기록 화면에서(`/records?note=<id>`로 그 노트만)
- **시험 정리**: 버튼은 [범위 기록], 범위 노트들의 기록을 노트 이름과 함께 읽기만 한다(이해도는 합치지 않는다, [기록 남기기] 없음). 시험 정리 자체는 복습일이 없다 — 기록이 붙어도 홈 복습 목록 · 사이드바 복습 점에 나오지 않는다
**이유**: 외부 검토(ChatGPT 4차, 11/8): 노트 끝 기록 영역 제거 · 위쪽 [기록] 창 찬성, 오른쪽 고정 패널 반대(강의 PDF · AI 창과 자리 다툼), 시험 정리 기록 창은 읽기 전용. 지난번 화면별 최종안("기록 목록은 학습 기록 화면에만, 다른 화면은 한 줄 + 링크")과도 맞춘다.
**폐기**: 노트 끝의 학습 기록 영역, 오른쪽에 계속 펼쳐 두는 기록 패널, 시험 정리의 "준비 기록"(노트 끝에 범위 노트 기록 모음), 시험 정리에서 기록 남기기.

### D-37. 구조를 여기서 굳힌다: 계산은 기록에서만, 태그 빼기, 기록 창은 한 줄 (D-30 · D-36을 줄인다)
고칠 때마다 다른 데서 문제가 나온 이유는 같은 값이 여러 곳에서 다르게 정해졌기 때문이었다(2026-11-08 구조 점검표, ChatGPT 5차 검토).
- **계산은 기록에서만**: 노트의 상태 · 이해도 · 다음 복습일은 학습 기록(오답 노트는 문제 표시)으로만 계산한다. 예전 속성 창에서 손으로 고른 `status` · `understanding`은 읽지 않는다(값은 지우지 않고 그대로 저장). 남아 있으면 기록을 남겨도 상태가 안 바뀌거나 복습이 숨었다
- **범위표의 다음 복습일**: 노트가 여러 시험 범위에 있으면 가장 가까운 시험 전날로 당긴다(홈 복습 목록과 같은 `examDeadlines`). 다른 시험 때문에 당겨졌으면 "(앞 시험 전날)"
- **태그**: 노트 끝에서 뺀다. 태그를 읽는 곳(검색 · 거르기 · 분석)이 없었고, 과목 · 폴더가 이미 노트를 나눈다. 데이터는 그대로 둔다
- **[기록] · [범위 기록] 창**: 요약 한 줄 + 마지막 기록 한 줄 + [기록 남기기] + 모두 보기. 목록은 학습 기록 화면에만(D-36의 "최근 3개"를 줄인다. 4차 검토는 목록을, 5차는 빼기를 권해 둘의 중간)
- **11/15까지 구조 동결**: 이후에는 핵심 흐름이 끊기는 버그, 데이터 손실, 계산 오류만 고친다
**이유**: 같은 사실을 두 군데서 정하면(수동값과 기록, 시험 정리와 홈의 시험 전날) 한쪽을 고칠 때 다른 쪽이 어긋난다. 읽는 곳 없이 저장만 하는 값(태그)은 미완성 기능이다(AGENTS.md "흐름").
**폐기**: 손으로 고르는 노트 상태 · 이해도, 노트 태그 화면, 기록 창의 최근 기록 3개 목록.

### D-38. 홈에 오늘 시간표: 계획은 글자, 실제 공부는 세로줄 (D-37 "11/15까지 구조 동결"의 예외)
할 일에 시각이 없어 "오늘 언제 뭘 하지"가 안 보였고, 기록에는 저장한 시각만 있어 몇 시에 공부했는지 그릴 수 없었다(2026-11-10 이재윤, 노션 "데일리 리포트 스터디 플래너"를 보고).
- 데이터: `todos.start_min`(그날 0시부터 센 분, null 가능), `study_records.started_at`(null 가능). 화면은 한 시간 단위로 고르지만 분으로 저장해, 30분 단위로 바꿔도 칸을 고치지 않는다
- 한 시간에 한 줄인 목록(노션식), 연한 남색 판. 줄의 글자는 계획(시각을 정한 할 일, 체크리스트와 같은 체크 상자), 시각 옆 세로줄은 실제 공부(시작 시각이 있는 기록과 돌아가는 타이머, 분 단위로 채움)
- 하루 전체가 한 목록이고, 여덟 시간쯤 보이는 창 안에서 스크롤한다. 열면 지금 한 시간 전이 맨 위(2026-11-12, 처음에는 지난 시간을 한 줄로 접었다): 접기는 새벽 · 아침에 줄이 20개 넘게 펼쳐져 오른쪽 열이 길어졌다. 스크롤 창은 몇 시에 열어도 높이가 같다
- 줄 사이 선은 긋지 않는다. 무언가 들어 있는 시간은 흰 블록, 빈 시간은 빈 공간(2026-11-12 이재윤): 넣은 곳이 바로 보이고 빈 시간이 한 덩어리로 읽힌다. "지금" 글자도 뺐다(굵은 시각과 세로줄의 점으로 충분)
- 전날에서 넘어온 할 일은 시각 없이 보인다(어제 정한 시각이 오늘 시간표에 박히지 않게). 시각을 다시 정하면 오늘 할 일이 된다
- 시작 시각을 모르는 기록은 그리지 않는다. 시각을 지어내지 않는다(기록 창의 "시작"은 선택)
- 시각을 정한 할 일은 체크리스트와 시간표 양쪽에 보인다. 넣고 고치고 지우는 곳은 체크리스트 하나
- 학습 계획과의 연결(2026-11-11): 시간표 아래 "진행 중인 계획에서 오늘 할 만큼"에 계획마다 오늘 몫(시간 목표가 있으면 남은 시간 ÷ 남은 날, 10분 단위)이 나오고 [시간표에 넣기]로 시각을 고르면 그 이름의 할 일이 된다. 연결을 저장하는 칸은 만들지 않았다: 할 일 이름이 계획 이름으로 시작하면 이미 넣은 것으로 본다. 계획의 진행은 여전히 학습 기록으로만 센다
**이유**: 계획한 시간과 실제 공부한 시간을 한 칸에서 같이 보는 것이 "기록을 다음 학습으로 잇는다"는 서비스 방향과 맞다. 발표 전 구조 동결(D-37)을 깨는 대신 새 칸은 둘 다 null 가능이고 기존 계산에는 쓰지 않는다.
**폐기**: 계획 · 공부 두 칸에 상자를 얹는 달력형(좁은 열에서 한쪽이 비고 글자가 작았다), 회색 판에 17줄을 다 펼친 목록(대부분 빈 줄), 지난 시간 접기, 줄마다 긋는 선, 넣은 줄에만 긋는 위아래 선(선이 띄엄띄엄 나와 어중간했다), "공부 n분"을 작은 회색 글자로만 보이기, 시(0~23)만 저장하는 칸, 시작 시각이 없는 기록에 "지금 − 공부 시간"을 넣기.
