# 결정 기록

무엇을 정했는지, 왜 정했는지, 무엇을 버렸는지를 적는다. 새 결정은 맨 아래에 번호를 이어 붙인다.
한 항목은 3~5줄이면 충분하다. 버린 방향은 "폐기"로 표시해서 같은 시도를 반복하지 않게 한다.

작성 시작: 2026-10-12

---

### D-01. 학습 기록은 페이지에 딸린 데이터다
학습 기록을 별도 페이지 타입이나 사이드바 트리 노드로 만들지 않는다. 한 페이지에 기록이 여러 개 쌓이는 구조다.
**이유**: Home과 학습 분석이 같은 페이지/기록 데이터를 공유해야 하고, 페이지가 학습의 중심이어야 한다.

### D-02. 복습과 AI는 페이지 타입이 아니다
복습은 "기존 페이지로 돌아가 다시 공부하는 행동", AI는 "열려 있는 페이지에서 쓰는 도구"다.
"+ 새 페이지"에는 복습하기, 문제 풀기, AI 도구, 학습 분석을 넣지 않는다.

### D-03. 페이지 트리는 깊이를 고정하지 않는다
그룹과 페이지를 자유롭게 중첩한다. 예시 데이터의 4단계는 예시일 뿐이다. 페이지 아래 그룹/페이지, 드래그 앤 드롭 이동을 지원한다.

### D-04. 페이지 종류는 템플릿 레지스트리로 관리한다
페이지 종류마다 `if` 분기를 늘리지 않고, `lib/templates.ts`의 배열에 템플릿을 추가하는 방식으로 확장한다.
D-23 이후 템플릿은 "새 페이지의 시작 블록"만 정한다(본문 컴포넌트를 템플릿마다 두지 않는다).

### D-05. 학습 기능이 켜지면 모든 페이지가 같은 속성/기록/AI 도구를 가진다
**폐기**: 속성 패널(이해도, 학습 시간 등)을 학습 노트에만 허용하는 방식. 데이터는 학습 기록에서 어차피 계산되는데 한쪽에만 보여주는 "가짜 차이"였고, 빈 페이지 사용자가 자기 데이터를 못 보는 문제가 있었다.

### D-06. 학습 노트와 빈 페이지의 진짜 차이는 "시스템이 내용을 이해하는가"다 (D-23으로 대체)
D-23 이후 구조는 페이지 종류가 아니라 블록에 있다: 핵심 개념/헷갈린 점 블록이 있으면 어느 페이지든 복습 카드와 헷갈린 점 추적이 된다. 아래는 당시 기록.
학습 노트는 본문이 구조화(핵심 개념, 헷갈린 점)되어 있어서 시스템이 내용을 안다. 그래서 복습 모드, 헷갈린 점 해결 추적, Home 복습 후보, 세션 타이머 자동 추적이 학습 노트(`locked-on`)에서만 동작한다. 빈 페이지는 자유 본문이라 시스템이 내용을 모른다.
**이유**: 정보량이나 겉모습이 아니라 "구조가 있어야만 가능한 기능"으로 구분해야 둘이 다른 도구로 느껴진다.

### D-07. 학습 노트 2컬럼 레이아웃은 폐기했다
**폐기**: 학습 노트만 좌측 속성 패널 + 우측 본문의 2컬럼으로 만든 시도. UI 통일감만 깨지고 기능 차이는 만들지 못했다. 지금은 모든 페이지가 같은 1컬럼 틀을 쓴다.
같은 이유로 색 틴트나 아이콘만으로 차별화하는 접근도 효과가 없었다(차이가 페이지를 열었을 때 보이지 않아서).

### D-08. 복습 추천은 학습 노트만, 누적 통계는 모든 페이지 (D-23으로 대체: 학습 기능이 켜진 모든 페이지가 후보)
Home의 복습 추천("오늘 할 일"의 복습할 노트)은 `locked-on` 페이지만 후보로 삼는다. 학습 분석의 총 학습 시간, 기록 수, 평균 이해도는 빈 페이지의 기록도 포함한다.
**이유**: 실제로 공부한 시간은 사실이므로 통계에는 넣고, "복습하라"는 능동 추천은 학습 노트로 약속한 페이지에서만 한다.

### D-09. 학습 시간은 홈의 전역 세션 타이머로 자동 기록한다
페이지마다 타이머를 두지 않는다. 홈에서 세션을 켜 두면 방문한 학습 노트별로 시간이 자동으로 나뉜다. 빈 페이지 방문은 기록하지 않는다.
**이유**: 한 번 앉아서 여러 과목을 오가는 실제 공부 패턴에 맞고, 페이지마다 버튼을 누르는 걸 잊을 일이 없다. 수동 입력(기록 폼)도 대안으로 남겨 둔다.

### D-10. 세션 시간 중복 집계는 "기록이 있으면 기록이 우선"으로 한다
**폐기**: 요약 모달 버튼으로 만든 기록만 "기록됨"으로 표시하던 방식. 복습 완료나 직접 추가에서는 같은 시간이 두 번 집계됐다.
지금은 그 세션 동안 그 페이지에 기록이 하나라도 있으면 측정 시간을 빼고 기록값만 쓴다. 사용자가 미리 채워진 시간을 줄이면 그 값이 확정값이다.

### D-11. 비정상 종료된 구간은 "마지막 활동 시각"에 닫는다
탭을 닫거나 자리를 비운 시간이 학습 시간에 들어가면 안 된다. 30초마다 마지막 활동 시각을 저장하고, 다시 열릴 때 그 시각으로 닫는다. 30분 이상 활동이 없었으면 세션도 그 시각에 자동 종료한다.

### D-12. hydration 오류는 서버 스냅샷을 고정해서 푼다
현재 날짜 같은 브라우저 값은 서버 스냅샷을 null로 두고 마운트 이후에만 읽는다(`hooks/use-today.ts`).
**하지 않는 것**: `suppressHydrationWarning`으로 경고를 숨기기, 임의의 고정 날짜 넣기, 렌더 중 `new Date()` 직접 사용.

### D-13. AI 기능은 UI 목업이고 실제 AI는 후순위다 (D-22로 대체)
요약하기/문제 생성하기는 화면만 있다. 실제로 학습 데이터를 분석하거나 추천하는 것처럼 표현하지 않는다. 실제 AI 연동은 DB와 데이터 연결 이후 단계다.

### D-14. 협업은 repo 문서 + PR로 한다
**폐기**: 변경이 생길 때마다 긴 설명 프롬프트를 상대에게 붙여넣는 방식(보내는 순간부터 낡는다).
`main`에 직접 작업하지 않고 기능별 브랜치 → PR → 리뷰 → merge. 공유할 내용은 `docs/`와 PR 설명에 둔다. 데이터 구조를 바꿀 때는 구현 전에 문서만 바꾼 PR로 먼저 합의한다.

### D-15. 첨부는 본문 블록으로, 페이지 메뉴는 한 컴포넌트로 공유한다
파일과 이미지는 별도 목록이 아니라 본문 블록(image, file)으로 넣는다. 첨부 진입은 본문 버튼이 아니라 페이지 헤더 ⋯ 메뉴의 "파일 첨부"(그리고 드래그 앤 드롭, 붙여넣기)다. 사이드바와 페이지 헤더의 ⋯ 메뉴는 같은 컴포넌트(PageActionsMenu)를 쓴다.
**이유**: 첨부가 글 사이에 자연스럽게 들어가고, 같은 동작을 두 곳에 복사하면 서로 어긋나기 때문이다.

### D-16. 그림은 이미지가 아니라 획 데이터로 저장한다
그림 블록은 획(좌표 목록, 도구, 색, 굵기)을 블록 너비 기준 비율 좌표로 저장한다.
**이유**: 화면 크기가 바뀌어도 모양이 유지되고, 획 단위로 지우거나 되돌릴 수 있으며, 이미지보다 용량이 작다.

### D-17. v0의 Publish로 main에 바로 합치지 않는다
**폐기**: v0에서 Publish를 눌러 main에 바로 반영하던 방식. 검사 없이 main이 바뀌어서 2026-10-17에 main의 빌드가 깨졌다(서버 컴포넌트가 클라이언트 저장소를 import).
모든 변경은 브랜치 → PR → PR의 Vercel 미리보기 빌드가 Ready인지 확인 → merge 순서로 한다.

### D-18. 인증은 Supabase Auth 이메일 로그인으로 한다
이메일 + 비밀번호로 가입하고, 이메일 인증을 거친다. 세션은 `@supabase/ssr` 쿠키로 유지하고, 로그인하지 않은 요청은 `proxy.ts`가 `/login?next=...`로 보낸다(PR #15). 소셜 로그인과 비밀번호 찾기는 아직 없다.
화면은 Supabase를 직접 부르지 않고 `lib/auth.ts`의 함수(`signIn`, `signUp`, `signOut`, `useCurrentUser`)만 부른다(PR #14). `lib/workspace.ts`와 같은 원칙이다.
**이유**: DB도 Supabase로 가므로 같은 사용자 id(`auth.users`)로 RLS를 걸 수 있다. 별도 서버 없이 가입/인증 메일/세션 갱신이 해결된다.

### D-19. merge는 Vercel 프로젝트 주인(이재윤)이 누른다
Vercel 프로젝트는 이재윤의 Hobby(무료) 계정에 있다. Hobby는 비공개 저장소에서 계정 주인이 만든 커밋만 배포하고, 다른 사람의 커밋은 "Deployment was blocked"가 된다. merge 커밋의 작성자는 merge 버튼을 누른 사람이다.
2026-10-20~21에 김준혁이 merge한 PR #16~#22가 모두 배포되지 않았고, 대시보드의 Redeploy도 같은 이유로 막혔다. 이재윤이 #12를 merge해서 그 시점의 main 전체가 배포됐다.
그래서 리뷰와 승인은 둘 다 하고, merge 버튼은 이재윤이 누른다.
**대안(지금은 안 함)**: 저장소를 공개로 바꾸기(누가 merge해도 배포됨), Vercel Pro로 올리고 팀원 추가(유료).

### D-20. 체크리스트의 못 끝낸 할 일은 다음 날로 넘어온다
오늘의 체크리스트는 오늘 할 일 + 지난날 못 끝낸 할 일을 보여준다. 끝낸 할 일은 끝낸 날에만 보인다. 페이지·계획과는 연결하지 않는다(R10).
**이유**: 공부할 일은 하루에 못 끝내는 경우가 많고, 넘어오지 않으면 매일 다시 적어야 한다. 처음 기획서의 "학습·과제 수행 여부 체크"를 가장 작은 형태로 만든다.
**하지 않은 것**: 날짜별 체크리스트 기록 보기, 반복 할 일, 페이지·계획 연결.

### D-21. Home은 "오늘 할 일" 한 카드로 시작한다
복습할 노트, 진행 중인 계획, 체크리스트를 홈 맨 위의 한 카드로 모은다(R11). 전에는 오늘의 우선 학습, 복습 목록, 체크리스트가 따로 있었고 계획은 홈에 없었다.
**이유**: "학습 OS"는 기능을 나열하는 것이 아니라 오늘 무엇을 할지 한곳에서 정해 주는 것이다. 계획은 진도가 보여야 행동으로 이어진다.
**하지 않은 것**: 계획에 숫자 목표(목표 시간)를 저장해 진도율을 계산하기. DB 구조 변경이 필요해 발표 뒤에 정한다.

### D-22. AI 학습 도우미는 Claude API를 서버 경로에서 부른다
학습 페이지 아래의 채팅에서 페이지 내용(제목, 본문 또는 학습 노트, 최근 학습 기록 3개)을 맥락으로 Claude에게 묻는다. 빠른 질문(요약, 정리 노트, 확인 문제, 헷갈린 점 설명)과 자유 질문을 지원하고, 답은 "AI 정리" 제목과 함께 본문 끝에 블록으로 추가할 수 있다.
- 키는 서버 전용 환경 변수 `ANTHROPIC_API_KEY`, 모델은 `AI_MODEL`(기본 `claude-sonnet-5-5`). 로그인한 사용자만 부를 수 있고, 한 사용자당 분당 10회(서버 인스턴스별 대략적 제한)
- 대화 기록은 저장하지 않는다(페이지를 떠나면 사라진다). 그림과 PDF 위 필기는 AI에 넘기지 않는다
- PDF(2026-10-23 추가): 채팅 위 "PDF도 같이 보기"에서 고른 PDF(최대 2개, 합쳐 50쪽)를 질문과 함께 보낸다. 브라우저는 Storage 경로만 보내고, 서버가 사용자 세션으로 Storage에서 받아(RLS로 본인 파일만) Claude에 document 블록으로 넘긴다. Storage에 저장된 PDF만 고를 수 있다. 매 질문마다 PDF를 다시 보내므로 첫 메시지에 붙이고 prompt cache를 건다
**이유**: 팀이 Claude를 쓰기로 했고(2026-10-22), 키를 브라우저에 노출하지 않으려면 서버를 거쳐야 한다. 정해진 버튼 두 개(요약, 문제)보다 사용자가 원하는 정리·문제를 직접 요청하는 쪽이 학습 도구로 쓸모가 크다.
**왜 50쪽인가**: Claude는 한 요청에 100쪽(32MB)까지 받지만 쪽당 1,500~3,000토큰이라 비용이 크다. 강의 자료 한 단원 정도를 기준으로 잡았다.
**다음 단계**: 만든 문제를 퀴즈로 풀고 결과를 학습 기록에 남기기, 이미지 첨부 넘기기.

### D-23. 모든 페이지는 빈 페이지 + 블록이고, 템플릿은 시작 블록만 정한다
학습 노트의 고정 섹션(오늘 배운 내용 / 핵심 개념 / 헷갈린 점)을 블록으로 바꿨다. 핵심 개념(`concept`)과 헷갈린 점(`confusion`)은 블록 종류이고, 템플릿(학습 노트 · 강의 노트 · 오답 노트 · 시험 정리)은 이 블록들로 미리 채운 시작점이다. 학습 기능은 모든 페이지에서 켜고 끌 수 있다.
**이유**: 노션처럼 "빈 페이지에 필요한 것만 더한다"는 방향. 고정 섹션은 강의 필기·오답 정리처럼 다른 모양의 공부를 담지 못했고, 학습 노트와 빈 페이지가 따로 노는 두 가지 편집기였다.
**DB를 바꾸지 않은 방법**: `template_id`는 `"study-note"`/`"blank"`만 쓰고, 옛 `note` 컬럼은 읽어서 블록으로 보여주기만 한다(쓰지 않음). 발표 직전이라 이전 빌드로 되돌려도 데이터가 그대로 보이게 하려는 것.
**폐기**: `studyMode: "locked-on"`(학습 노트는 학습 기능을 끌 수 없음), 템플릿마다 본문 컴포넌트를 두는 방식(`StudyNoteBody`/`FreeBody`).
